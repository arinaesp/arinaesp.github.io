lead the ship — bilingual education platform

A 40-page platform, built in four days.

A bilingual (Russian/English) education platform for young people in Kyrgyzstan and Central Asia — a project-launch program plus a catalog of short courses, built as a full static Astro site: content collections, structured data on every page type, self-hosted subsetted fonts, and a GitHub Actions deploy pipeline. Designed and built solo, end to end.

what it is

The platform

Lead the Ship has two pillars: a project-launch program that guides teenagers and young adults through building a real project and using that experience for university applications, and a catalog of short courses and masterclasses — AI, essay writing, English, public speaking, design — taught by young experts, covering skills the school system doesn't. The whole site is bilingual: Russian as the primary language, English as a full parallel track, not a machine-translated afterthought.

40+ Pages, built and verified across both language versions
2 Full languages — Russian primary, English parallel, native copy in both
6+ Distinct JSON-LD schema types: Course, EducationalEvent, FAQPage, ItemList, LearningResource, Organization
engineering

What the build actually required

Font choices were verified, not assumed. Two fonts specified early in the design brief — Space Grotesk for display, Instrument Serif as a secondary face — turned out to have zero Cyrillic glyphs when checked directly against their cmap tables with fontTools. Both were dropped and replaced with Cyrillic-native alternatives (Golos Text for display, verified to cover all six Kyrgyz-specific letters as well as standard Cyrillic) — caught before shipping broken Russian headings, not after.

Content is structured for a future backend without needing one yet. Courses, missions, and resources are built as Astro content collections — markdown/JSON entries rendered at build time — using the exact same page templates and JSON-LD output a database-backed version would use later. Swapping the content source to a CMS or API in a future phase shouldn't require touching a single template.

Built for AI discoverability, not just search engines. A structured llms.txt at the site root, and a robots.txt that explicitly allows GPTBot, ClaudeBot, and PerplexityBot — plus JSON-LD structured data validated against Google's Rich Results Test on every distinct page type, and custom bilingual 404 handling that accounts for a real GitHub Pages constraint: project sites only ever serve one root 404.html, so per-path 404s for the English subpath can never actually trigger and had to be designed around rather than assumed away.

Deploy pipeline built for GitHub Actions, not branch-based Pages. A custom GitHub Actions workflow builds the Astro site and deploys the Pages artifact directly, avoiding a real Jekyll-processing gotcha that branch-based GitHub Pages deployments hit — documented directly in the workflow file for future reference, not left as tribal knowledge.

design system

A deliberately anti-generic visual identity

The design brief for this project explicitly ruled out the default AI-generated aesthetic before building anything: no cream-and-terracotta palette, no gradient hero with stock photos, no rounded-corner card grids with drop shadows, no generic "empowering tomorrow's leaders" language. The visual system — a constrained neo-brutalist, zine-meets-launchpad aesthetic with a deep indigo and olive-chartreuse palette, thick charcoal borders, and mono-font "mission control" readouts for stats and metadata — was chosen to earn a specific, concrete reaction: would a 16-year-old in Bishkek actually screenshot this for their story.

stack

Built with

Astro (static output, i18n for ru/en), content collections for courses, missions, and resources, self-hosted WOFF2 fonts subsetted with fontTools to Latin + Cyrillic + Kyrgyz glyph ranges, @astrojs/sitemap, JSON-LD structured data hand-built per page type, and a GitHub Actions deploy workflow using withastro/action and actions/deploy-pages.
